# L&D Module Flow Analysis (Learning & Development)

## 1. Flow Diagram

```
[Needs Analysis (TNA / e-SAT)]
  Trigger: Admin creates TNA Form in LDPortalNeedsAnalysis.jsx
  API: POST /api/ld/tna
  Tables: tna_forms (status='active'), tna_questions
  Submission: Employee fills self-assessment in /ld-employee/self-assessment
  API: POST /api/ld/tna/submit
  Tables: tna_responses, tna_answers, ld_ipcrf_records
       │
       ▼
[Program Design & Proposal Submission]
  Trigger: Employee proposes program or Admin designs PD program in LDPortalPDProgramDesign.jsx
  API: POST /api/ld/proposals, POST /api/ld/programs
  Tables: ld_program_proposals (status='pending_review'), ld_programs, ld_plans, ld_objectives
       │
       ▼
[Quality Assurance & NEAP Alignment]
  Trigger: HR Admin reviews proposal & QA standards in LDPortalQualityAssurance.jsx
  API: POST /api/ld/proposals/:id/review, POST /api/ld/programs/:id/qa-approve
  Tables: ld_program_proposals (status='approved'/'rejected'), ld_programs (is_qa_approved=1)
       │
       ▼
[Conduct, Registration & Attendance Monitoring]
  Trigger: Employee registers/attends session in /ld-employee/attendance
  API: POST /api/ld/programs/:id/register, POST /api/ld/programs/:id/checkin
  Tables: ld_training_participants, ld_attendance, ld_session_checkins, ld_program_test_submissions
  Monitoring: Admin tracks real-time check-ins in LDPortalAttendanceMonitor.jsx
       │
       ▼
[Evaluation, M&E & HRD Database Archiving]
  Trigger: Employee completes post-training survey in /ld-employee/my-records & Admin generates report
  API: POST /api/ld/evaluation/submit, POST /api/ld/reports/completion
  Tables: ld_evaluation_responses, ld_evaluation_answers, ld_program_completion_reports, ld_program_me_summaries, ld_employee_training_records
```

## 3. Discrepancies & Red Flags

1. **Four Coexisting UI Frontends**:
   - Legacy Admin (`/ld/*`) vs New Admin Portal (`/ld-portal/*`).
   - Legacy Employee (`/jobs/my-learning`) vs New Employee Portal (`/ld-employee/*`).
   - Both legacy and new portals hit overlapping API endpoints (`/api/ld/programs`, `/api/ld/tna`), but use different database tables for certain operations.
2. **Dual Program Table Abstraction**:
   - Legacy system uses `ld_trainings` and `ld_training_participants`.
   - New Portal system uses `ld_programs` and `ld_employee_training_records` (Migration 053).
   - Compatibility router (`routes/ld/compatibility.js`) acts as a bridge shim to adapt legacy requests to new table schemas.
3. **`participant_count` SQL Calculation Issue**: Identified earlier in server logs where `participant_count` SQL subquery in `programController.js` joins on `ld_training_participants` instead of `ld_employee_training_records`, returning 0 count for new portal registrations.
